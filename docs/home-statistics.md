# 首页经营统计规则

首页通过 `POST /api/v1/dashboard/query` 读取服务端真实业务快照，输入仅为 `period: 7d | 30d`。日期和权限由服务端确定；不接受客户端指定企业、权限、金额或任意日期。使用现有 SQLAlchemy 声明式模型，并在同一 ORM 只读事务内读取当前账号权限和业务数据，无新增表或迁移。

## 时间和金额

- 时间沿用已存单据的 UTC，页面显示 UTC 范围和快照时刻。近 7/30 天包含今天，今天截至快照时刻；比较期是之前不重叠的等长自然日。今天尚未结束，不把比较结果称为完整周期业绩。
- 销售业务净额复用应收来源：已确认销售出库为正、退货为负、各自冲销反向，维修检验交还结案的服务费为正、服务费更正为负。每个事件按自己的确认或更正日期计入，不回删原发生日。
- 采购业务净额复用应付来源：已确认采购入库为正、采购退货为负、各自冲销反向。库存核价不是历史自由入库的订单单价，不能替代缺失采购价格。
- 逐行金额沿用现有人民币分位四舍五入规则，服务端用 Decimal 汇总。响应分别保留 `amount`、已定价部分 `known_amount`、缺价行数 `unpriced_count` 和来源行数。任一行缺价时 `amount` 为 null，页面显示“待定价”，并暂停不完整趋势；没有来源时金额为零。
- 业务净额不代表资金到账、未结往来余额、毛利或已过账总账收入。负向净额在趋势图中保留，提供零线与逐日金额表。金额展示以整数分保留大额精度，图形坐标为近似值；精确数值以表格为准。
- 前一期净额为零或负数时不计算增长率，两期零净额另行说明；缺价也不生成增长率。最近 100 行来源显示原单据、订单、行号、金额与时间，总金额仍来自全部行。完整来源由既有应收应付页面查看。

## 当前状态

待处理订单和库存概览不受所选日期限制，页面明确标记“当前状态”。

- 销售/采购待处理订单包含草稿及已确认、部分收发且仍有剩余收发数量的订单；取消、全量收发完成的订单不计入。有效收发排除已冲销单据。退货另记净交付，不重新打开原订单的收发配额，沿用原业务规则。
- 生产待处理工单包含草稿、已下达和生产中工单；完工交接分别统计待检验和待入库单据。
- 库存逐仓库、物料用 Decimal 累计全部流水，统计数量大于零的组合、拥有正库存的不同物料及负数组合。不把件、箱等不同计量单位相加。物料尚无安全库存规则，因此没有模拟低库存预警。
- 有效单据构成按整单统计：期间确认且当前未冲销的销售出库、采购入库、生产完工和仓库调拨。多行单据只算一单；后续冲销会影响当前有效构成，因此该图不是历史固定归档。零单据呈现空环与零数量。

## 权限和客户端状态

所有已登录账号可以进入首页。金额、趋势与来源要求 `finance.view`；销售数量要求 `sales.view`；采购数量、库存及调拨要求 `inventory.view`；生产数量要求 `production.view`。服务端按每个领域授权后才查询并返回，未授权领域为 null。未授权不能显示为零，也不增加原有账号权限。

首页使用 Pinia 状态和固定 Electron IPC，主进程仅发送合法期间并校验响应结构。换号、撤权、切换服务端身份/证书、断线和切换期间均清除旧快照，使迟到响应失效。进入页面、恢复连接或改变统计范围重新读取；刷新按钮手动更新，不承诺后台自动推送。查询失败提供重试，旧结果不冒充最新值。

## 验证边界

测试覆盖真实收发、分批未完订单、草稿/取消/完成、跨期冲销、退货更正、维修交还收费和反向来源、缺价、未来事件排除、UTC 范围、逐日汇总、生产状态及撤权；桌面测试覆盖 IPC 白名单、响应异常、整数分展示、负数图形和迟到响应。本需求后端 373 项、桌面单元测试 277 项通过，`npm run typecheck` 和 `npm run build` 通过。

组件浏览器检查覆盖 1440 像素明色、960 像素暗色，以及 7/30 天切换、逐日表、来源展开、查询失败、断线、无权限、缺价和期间无记录。检查使用独立临时数据库和明确标注的模拟业务单据，页面沿用既有首页布局与明暗主题，复用 AppButton、AppCollapseItem 和 WorkspaceTable。上述检查不等同于真实客户或 Windows/macOS 组合实机验收，设备与局域网运行验收仍按 [实机验收清单](lan-host-acceptance.md) 单独进行。
