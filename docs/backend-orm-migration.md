# 后端 ORM 迁移清单

后端采用 SQLAlchemy 2.0 声明式模型，模型位于 `app/core/models.py`，会话和事务边界位于 `app/core/orm.py`。金额字段沿用精确文本存储与 Decimal 运算，不改为浮点数。现有数据库版本迁移仍负责历史结构升级；不要使用 `create_all` 冒充旧库迁移。

| 模块 | 当前状态 |
| --- | --- |
| 库存计价、人工库存核价 | 已使用 ORM 模型查询与写入 |
| 生产成本、人工领料核价、费用、完工成本结算及冲销 | 已使用 ORM；完工更正与结算依赖检查共用同一会话 |
| 账号、角色、权限、导航图标 | 已使用 ORM；令牌撤销、最后管理员保护与修改审计在写事务中处理 |
| 供应商、物料、供货关系及供应商分页查询 | 已使用 ORM；保留唯一性、引用保护、级联删除及一致快照分页 |
| 采购申请/订单/收货/入库/退货 | 已使用 ORM；申请额度、待入库预留、订单状态、退货待出库闸口与流水共用写事务 |

现有业务数据访问迁移已完成，现有 86 张表有静态声明式模型，包含科目、期间、第 41 版手工凭证，第 42 版期初余额、明细和审计，以及第 43 版期间结账证据。数据库为第 43 版，接口字段、权限和单据状态没有因 ORM 改变。模型不在运行时反射，也不在启动时创建或替换历史表。已移除旧完工接口的 SQLite/ORM 兼容读取。

底层例外仅限数据库结构升级与初始数据迁移、SQLite 事务/外键/超时设置、在线备份 API 和备份完整性诊断。这些操作不属于业务查询或单据写入，不能用普通 ORM CRUD 替代。备份中的实例身份读取通过 ORM，仍用只读连接，错误路径不创建空库。

回归测试检查业务模块不再导入旧连接或执行 SQL 字符串，并模拟数据库写入后的故障，核对库存、单据、订单额度及跨模块来源整体回滚。并发收货、入库、退货、调拨、完工与收付款继续由同一写锁保护。

每个转换模块必须核对旧接口字段、错误状态、权限、金额精度、来源审计和并发行为。只读会话使用同一快照；写会话在业务核对前取得 SQLite 写锁，异常回滚并释放连接。后续数据库支持需另外实现对应驱动与迁移，不因引入 ORM 就声称 MySQL 已可用。
