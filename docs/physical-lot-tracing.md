# 实物批次基础与追踪设计草案

第 56 版已建立实物批次、升级时的历史未识别期初、流水分配的静态 ORM 模型和只读差额诊断接口。现有收发、调拨与成本接口**尚未写入批次分配，也未提供批次写入页面**；下文的操作规则仍是待确认的设计草案。批次表示可核对的实物流向，不改变已确认的单公司、人民币和移动加权平均成本口径。生产“完工批次结算”目前是成本归集概念，不可当作实物批次。

## 已交付的基础能力

- 升级到第 56 版时，按仓库和物料精确累计旧库存流水，在新表中建立标记为 `legacy` 的历史未识别期初，并记录最后一笔旧流水 ID 与缺少实物证据的说明。原流水、订单和成本记录不改写；重复启动不重复建立期初。该步骤属于数据库结构及初始化迁移，使用底层 SQLite；应用业务读写使用声明式 ORM。
- `GET /api/v1/inventory/physical-lots/overview` 沿用 `inventory.view`，可按 `warehouse_id` 和 `material_id` 筛选。它返回逐批余额，以及库存总余额和批次余额的差额。`fully_allocated` 仅表示本次查询无差额，不证明每笔历史流水都具备真实批号；升级后的普通收发继续形成待分配差额。
- 服务端提供同一 ORM 写事务的批次分配方法，校验分配之和、物料、仓库可用量、精度和冲销引用；现有单据接口尚未调用它，不能把这一方法视为已完成业务接入。人工修复差额、批次创建、批次选择与现场核验接口均待后续需求。
- 只读工作台“实物批次”沿用 `inventory.view`，提供仓库/物料筛选、未分配差额、批次来源历史与正式库存台账入口。`GET /api/v1/inventory/physical-lots/{lot_id}/history` 返回历史未识别期初、后续逐笔分配、冲销关联及逐仓余额；无权访问返回 401/403，不存在的批次返回 404。客户端对响应形状及筛选来源作校验，断线、换号与撤权时清除旧证据。

## 身份、守恒与审计

- 同一物料的实物批次以稳定编号标识，跨仓调拨保留身份。库存流水仍是数量和成本的正式来源；每笔有数量的流水须拆成一条或多条带批次的数量分配，同一笔的分配和精确等于原流水数量。查询按仓库、物料和批次累计这些分配，并与原库存余额逐组合勾稽。
- 出库不能使用目标仓库不存在或数量不足的批次。一个单据可以消耗多个批次，每批数量精确到三位小数；写锁内再次校验，任何一行失败时整单及其分配回滚。
- 更正只追加原单据、原流水和原批次分配的反向记录，保留操作人、时间和原因。原批次已被后续单据使用时，依赖关系先更正或冲销，不得悄悄从另一批次抵扣。批次编号不得通过普通资料编辑改写历史来源。
- 物理批次余额与财务移动平均价分开核算。销售出库、生产领料与退货继续取发生时的移动平均成本，不能把批次编号误作批次成本法。

## 待确认的业务规则

1. 首版出库由操作员逐行指定批次，还是由服务端按先进先出或到期日自动分配？任一自动分配也必须在确认单据上固定实际结果；之后不能随库存变化重新解释历史。
2. 旧库的库存只有仓库与物料余额，没有真实批次证据。可以先建立明确标记为“历史未识别”的结存，再通过有原因和操作者的盘点拆分；也可以要求逐批建期初证据后启用追踪。无论选择哪种，都不能从旧采购、销售单据倒推不存在的物理批号。
3. 是否需要供应商批号、生产批号、生产/失效日期、保质期和序列号的唯一性规则？这些字段缺失时须显示“未提供”，不能凭订单号自动冒充供应商批号。

## 来源覆盖矩阵

| 来源 | 确认时的批次动作 | 冲销或退回时的约束 |
| --- | --- | --- |
| 采购入库、其他入库、合格完工入库 | 建立或引用实际入库批次，正向分配 | 原批次未被后续有效出库占用时，按原分配反向扣回 |
| 销售出库、其他出库、采购退货、生产领料 | 扣减来源仓库的实际批次 | 出库冲销按原分配回到原仓和原批次；退货需记录实际收回批次 |
| 仓库调拨及调拨冲销 | 两仓等量转移相同批次 | 目标仓已耗用的批次不能被原单冲销掩盖 |
| 销售退货、生产退料、采购退货冲销 | 记录回仓批次，与原来源建立核对关系 | 再冲销时只扣回该次实际回仓批次 |
| 盘点、库存调整及冲销 | 将差异明确归到批次，零差异不制造分配 | 冲销沿用原差异的批次；原批次不够则说明后续依赖 |

目前各来源均由 SQLAlchemy ORM 会话写入 `stock_movements`，但代码在多个业务目录中生成流水。实现时要逐个接入上述来源，覆盖新单、旧单升级、越仓、重复确认、并发超量和冲销后再确认的测试；不允许只在查询页按总量推断批次。现有只读页面已供有权账号查看批次结存、已分配流水和历史期初；实际收发单据中的批次录入、上下游核对及守恒接入仍须逐来源实现。
