# 实物批次追踪设计草案

本文是待确认的实现方案，当前库存、收发、调拨与成本接口**尚未提供实物批次追踪**。批次表示可核对的实物流向，不改变已确认的单公司、人民币和移动加权平均成本口径。生产“完工批次结算”目前是成本归集概念，不可当作实物批次。

## 身份、守恒与审计

- 同一物料的实物批次以稳定编号标识，跨仓调拨保留身份。库存流水仍是数量和成本的正式来源；每笔有数量的流水须拆成一条或多条带批次的数量分配，同一笔的分配和精确等于原流水数量。查询按仓库、物料和批次累计这些分配，并与原库存余额逐组合勾稽。
- 出库不能使用目标仓库不存在或数量不足的批次。一个单据可以消耗多个批次，每批数量精确到三位小数；写锁内再次校验，任何一行失败时整单及其分配回滚。
- 更正只追加原单据、原流水和原批次分配的反向记录，保留操作人、时间和原因。原批次已被后续单据使用时，依赖关系先更正或冲销，不得悄悄从另一批次抵扣。批次编号不得通过普通资料编辑改写历史来源。
- 物理批次余额与财务移动平均价分开核算。销售出库、生产领料与退货继续取发生时的移动平均成本，不能把批次编号误作批次成本法。

## 待确认的业务规则

1. 首版出库由操作员逐行指定批次，还是由服务端按先进先出或到期日自动分配？任一自动分配也必须在确认单据上固定实际结果；之后不能随库存变化重新解释历史。
2. 旧库的库存只有仓库与物料余额，没有真实批次证据。可以先建立明确标记为“历史未识别”的结存，再通过有原因和操作者的盘点拆分；也可以要求逐批建期初证据后启用追踪。无论选择哪种，都不能从旧采购、销售单据倒推不存在的物理批号。
3. 是否需要供应商批号、生产批号、生产/失效日期、保质期和序列号的唯一性规则？这些字段缺失时须显示“未提供”，不能凭订单号自动冒充供应商批号。

## 来源覆盖矩阵

| 来源 | 确认时的批次动作 | 冲销或退回时的约束 |
| --- | --- | --- |
| 采购入库、其他入库、合格完工入库 | 建立或引用实际入库批次，正向分配 | 原批次未被后续有效出库占用时，按原分配反向扣回 |
| 销售出库、其他出库、采购退货、生产领料 | 扣减来源仓库的实际批次 | 出库冲销按原分配回到原仓和原批次；退货需记录实际收回批次 |
| 仓库调拨及调拨冲销 | 两仓等量转移相同批次 | 目标仓已耗用的批次不能被原单冲销掩盖 |
| 销售退货、生产退料、采购退货冲销 | 记录回仓批次，与原来源建立核对关系 | 再冲销时只扣回该次实际回仓批次 |
| 盘点、库存调整及冲销 | 将差异明确归到批次，零差异不制造分配 | 冲销沿用原差异的批次；原批次不够则说明后续依赖 |

目前各来源均由 SQLAlchemy ORM 会话写入 `stock_movements`，但代码在多个业务目录中生成流水。实现时要逐个接入上述来源，覆盖新单、旧单升级、越仓、重复确认、并发超量和冲销后再确认的测试；不允许只在查询页按总量推断批次。首版页面应让有权限的人查询批次结存、批次流水及上下游来源，并能在实际收发单据中录入或核对批次。
