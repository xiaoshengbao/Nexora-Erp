# 总账科目与会计期间基础

本文记录单公司科目与期间基础，业务金额仍按人民币运行。科目和期间不会把已有单据自动转成凭证。[手工凭证](manual-journals.md)已另行提供独立审核、过账和冲销；[正式期初余额](opening-balances.md)提供首次启用的独立审核与确认；[期间结账与重开](period-closing.md)已另行提供；业务自动凭证与正式财务报表仍未实现。

## 科目

财务管理 → 总账科目支持建立、搜索、修改名称、启停和查看变更记录。当前采用平级科目，尚无父子科目或辅助核算。公司自行确定科目表，不预置或声称符合某套会计准则。

编码最多 32 位，以字母或数字开头，可包含点、横线、下划线，两端空格去除并统一大写，编码唯一。类别为资产、负债、权益、收入、费用、成本；正常余额方向为借方或贷方，建档人明确选择，支持备抵类科目的相反方向。

编码、类别和余额方向保存后固定，不提供删除。新科目为启用、版本 1。修改名称或启停必须填写原因并传入打开编辑器时的版本，有效修改后版本加一；过期版本和无变化返回 409。保存失败保留草稿与旧版本，用户核对刷新后的资料再打开编辑器，不能直接覆盖别人的修改。

## 期间

财务管理 → 会计期间支持建立、搜索、修改名称和查看变更记录。有效日期格式为 `YYYY-MM-DD`，结束不早于开始；范围包含首尾，不能与任意已有期间重叠，紧邻下一日可建立新期间。允许公司自定日期范围，不自动推断月度或年度方案。

编码规则同科目，编码唯一。编码及日期保存后固定，不提供删除；新期间为开放状态，名称修改需要版本和原因。手工凭证校验日期属于开放期间；[期间结账](period-closing.md)已提供顺序结账、倒序重开、余额证据归档和历史核价/成本分摊锁定。已结期间不能改名，也不能通过新增历史期间绕开锁期。

## 接口与权限

以下路径统一以 `/api/v1/finance` 开头：

| 接口 | 权限 | 内容 |
| --- | --- | --- |
| GET `/ledger-accounts` | `ledger_account.view` | 全部科目，按编码排序 |
| POST `/ledger-accounts` | `ledger_account.manage` | 编码、名称、类别、余额方向、依据；返回 201 |
| PUT `/ledger-accounts/{id}` | `ledger_account.manage` | 名称、启停、版本、原因 |
| GET `/ledger-accounts/{id}/changes` | `ledger_account.view` | 建立、修改快照与操作者 |
| GET `/accounting-periods` | `accounting_period.view` | 全部期间，按开始日期排序 |
| POST `/accounting-periods` | `accounting_period.manage` | 编码、名称、首尾日期、依据；返回 201 |
| PUT `/accounting-periods/{id}` | `accounting_period.manage` | 名称、版本、原因 |
| GET `/accounting-periods/{id}/changes` | `accounting_period.view` | 建立及名称修改记录 |

管理员与财务员默认拥有四项权限；其他角色须显式授权，查看与维护独立。不存在返回 404，非法字段、日期或额外字段返回 422；重复编码、重叠、过期版本返回 409。

第 40 版新增 `ledger_accounts`、`ledger_account_changes`、`accounting_periods`、`accounting_period_changes`，不改写旧业务、不推断历史科目或期间。业务读写统一 ORM，日志保留前后完整快照、原因、操作者、时间，与资料同一写事务提交；失败整体回滚。写锁和版本保护并发创建及修改。

## 验证范围

后端测试覆盖字段校验、独立权限、版本冲突、重复编码、包含首尾的重叠判断、紧邻期间、并发修改与建期间、审计失败回滚、39 版升级及重复迁移；桌面测试覆盖路由权限、固定 IPC 路径与字段、冲突草稿及撤权数据清理。浏览器预览验证页面展示和交互，不代替真实 Electron 与跨设备验收。

存在有效期初方案时，新增会计期间不得早于启用日；首次启用须选择最早会计期间的开始日期，且该期间必须开放。这是总账启用约束；历史成本锁定由期间结账单独提供。
