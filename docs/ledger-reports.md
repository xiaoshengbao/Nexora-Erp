# 已过账总账报表

当前为单公司、人民币的已过账凭证核对工具，沿用 `journal.view` 权限。科目选项、报表查询、凭证详情和审计均受服务端授权；不要求科目维护权限，不授予写权限。数据库当前为第 43 版，86 张静态 ORM 模型；正式期初另由独立表保存，不重写历史业务。

## 查询口径

- 试算平衡查询全部科目，包括停用和零余额科目。期初为已确认启用余额加开始日期之前已过账分录的借贷净额；本期借贷发生额包含开始、结束日期；期末为期初加本期借方减贷方。正净额展示借方余额，负净额展示贷方余额，零净额两方均为零，不强制沿用科目默认余额方向。
- 科目明细一次选择一个科目，按凭证日期、凭证编号、分录序号排序。每笔显示凭证依据、期间、当时的科目快照、摘要、借贷发生额及累计余额；同一科目的多条分录分别计入。没有本期分录时仍展示期初和期末余额。
- 只包含 `posted` 凭证。草稿、提交、批准、驳回及取消凭证均不计入；冲销凭证也须过账后才按反向分录计入。原凭证不会因关联冲销而从历史删除，跨日期范围时各凭证按自身日期计入。
- 金额用 Decimal 从精确文本汇总，不依赖 SQLite 将文本转为浮点数求和。科目、分录、期间、期初来源与审计、合计在同一 ORM 读取事务中取得；未结账数据可随后续过账变化。生成时间是本次读取的 UTC 时间，不是期间锁定时间。
- 科目列表名称为当前资料，分录名称为凭证固定快照。覆盖期间随查询返回，开放/已结状态表示期间当前状态；当次余额与业务来源证据需查看 [期间结账记录](period-closing.md)，实时查询不能替代归档。

## 接口与桌面

| 接口 | 作用 |
| --- | --- |
| GET `/api/v1/finance/ledger-reports/options` | 全部科目选项，包括停用科目 |
| POST `/api/v1/finance/ledger-reports/query` | `kind` 为 `trial_balance` 或 `account_ledger`，开始/结束日期为有效 `YYYY-MM-DD`，科目明细须传正整数 `account_id`，试算平衡须为空 |
| GET `/api/v1/finance/journals/{id}` | 读取单张凭证、分录、作者与冲销关联，用于报表下钻 |

全部要求 `journal.view`。输入无效、额外字段、日期倒置或错误查询范围返回 422；不存在科目/凭证返回 404；无授权返回 403；未登录返回 401。

桌面入口“财务管理 → 总账报表”使用现有 WorkspaceTable 和 Pinia。修改条件清除旧结果；过期响应不会覆盖新条件，撤权或退出清除报表、选项和详情。点击科目编码进入同日期的科目明细，点击凭证及冲销来源查看详情和审计，可返回原凭证或关联冲销凭证。读取失败可重试。

响应包含列、行、合计、筛选、期间、生成时间和带 UTF-8 BOM 的 CSV。CSV 从当前结果生成，附日期范围、科目范围与合计；没有本期分录时仍标明所选科目，文本做公式防护。桌面导出保存当前快照，取消保存不报告成功，不重新查询。后续过账可能使再次查询的结果不同，不改变已下载快照。

## 当前限制与验证

这不是资产负债表或利润表；[正式期初余额](opening-balances.md)已提供；[结账与重开](period-closing.md)已提供；尚无损益结转或业务自动凭证。未录入正式期初时，查询中的期初只是历史已过账金额累计，页面和 CSV 均明确标注，不能代替业务方期初验收。试算借贷相等也不能证明科目选择或原始票据正确。

单元测试覆盖首尾日期、期初结转、凭证日期排序、贷方/零余额、大金额精度、同科目多行、未过账排除、冲销过账、停用快照、权限、非法输入、CSV 公式防护及生成期间发生新过账时列表/导出一致。桌面测试覆盖固定 IPC、旧响应失效、撤权清理、详情关闭、错误重试和保存取消。浏览器验收使用独立临时数据库和模拟数据，不代替 Electron 实机、真实会计样例或局域网设备验收。

正式期初只在 `confirmed` 状态计入。查询开始日期早于启用日返回 409。响应 `opening_balance` 保存完整已确认来源、明细及操作审计，报表页面可点击期初依据查看同快照详情；沿用 `journal.view`，无需期初维护权限。CSV 元数据包含启用日、来源编号和计算口径。未确认、取消或撤销的方案不进入余额；零余额启用仍明确返回已确认来源。
