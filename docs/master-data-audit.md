# 供应商与仓库资料版本审计

第 62 版起，供应商和仓库档案各有从 1 开始的版本号。编辑必须提交当前版本和非空修改原因；服务端持有写事务后比较版本，资料已变化时返回 409，不允许后到的旧页面覆盖。编辑前桌面端重新读取单条档案，失败保留表单。新增、修改及允许的删除都在同一事务写入操作者、时间、原因与完整前后快照；审计失败时档案操作一起回滚。

删除仍受原有引用保护，默认 1 号主仓库不能删除；删除必须提交当前版本。审计表不以被删除的档案为外键，因此删除后仍可按编号读取历史。升级前的旧档案统一从版本 1 开始，但不推断历史修改人或补造旧审计记录。供货物料的绑定、解绑，以及删除物料时的级联解绑不属于本次档案字段审计范围，仍保留现有关系接口与权限。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/v1/suppliers/{id}`、`GET /api/v1/warehouses/{id}` | `inventory.view` | 编辑前重新取得当前版本 |
| `GET /api/v1/suppliers/{id}/changes`、`GET /api/v1/warehouses/{id}/changes` | `inventory.view` | 按编号读取全部升级后记录，已删除档案仍可读 |
| `GET /api/v1/supplier-changes`、`GET /api/v1/warehouse-changes` | `inventory.view` | 全局记录，默认每页 100 条，可用 `before_id` 继续向前读取，`limit` 为 1–500 |
| 原有新增、编辑、删除路径 | `catalog.manage` 或 `warehouse.manage` | 编辑提交 `version`、`reason`；删除以查询参数提交 `version` |

桌面供应商与仓库页提供“变更记录”，包含删除的档案和逐页加载；供应商选项及仓库列表增加版本字段，其他业务只按档案编号引用，不把版本写入单据。客户端与服务端需一起升级。接口输入无效返回 422；版本、名称冲突或资料无变化返回 409；不存在返回 404；无权限返回 403。

后端使用静态 SQLAlchemy ORM 模型 `SupplierChange`、`WarehouseChange` 和统一会话。迁移只对旧表增加版本列、建立两张审计表，不以 ORM `create_all` 替代历史数据库迁移。第 61 版升级、并发编辑、重复名称、删除后历史、授权及写入失败回滚由接口测试覆盖。
